WORKFLOW FLOWS (USER JOURNEYS)
================================================================================

1. CUSTOMER SHOPPING WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Customer (my-app/)
  ↓
Browse Products
  ↓ (GET /api/products)
Backend retrieves from MongoDB
  ↓
Display Product Listings
  ↓
User Adds to Cart & Checkout
  ↓ (POST /api/orders)
Backend creates Order document
  ↓
Razorpay Payment Processing
  ↓ (Webhook: /api/orders/payment-verification)
If payment success → Order confirmed
If payment fails → Abandoned Checkout record created
  ↓
Send Confirmation Email (Notification Service)
  ↓
Order appears in Admin Dashboard
  ↓
Admin updates Shipping (Selects logistics provider)
  ↓ (POST /api/shipping)
Shipping API creates shipment with carrier
  ↓
Tracking ID returned to Backend
  ↓
Customer receives Tracking Email
  ↓
Tracking Cron updates TrackingEvents every hour
  ↓ (GET from shipping carriers)
Customer checks tracking in my-app (GET /api/track)
  ↓
Order delivered


2. ADMIN MANAGEMENT WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Admin (admin/)
  ↓
Visit /login
  ↓ (POST /api/auth/login)
Enter credentials
  ↓
Backend validates against admins collection
  ↓
Returns JWT token & username
  ↓
Token stored in localStorage
  ↓
Dashboard loads (Protected)
  ↓ (All requests include JWT in Authorization header)
Admin can perform CRUD:
  
  Products Management:
    - View Products (GET /api/products)
    - Create Product (POST /api/products) → Cloudinary upload
    - Update Product (PUT /api/products/:id)
    - Delete Product (DELETE /api/products/:id)
  
  Collections Management:
    - Create/Update/Delete Collections
    - Assign products to collections
  
  Orders Management:
    - View pending orders (GET /api/orders)
    - Update order status (PUT /api/orders/:id)
    - View order details
  
  Shipping Management:
    - Configure shipping providers
    - Set shipping rates
    - Assign shipments to orders
    - View tracking updates
  
  Notifications:
    - View sent notifications log
    - Resend notifications manually


3. ABANDONED CHECKOUT RECOVERY WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Customer initiates checkout but doesn't complete payment
  ↓ (GET /api/orders/:id - order in pending state)
Cron job runs every 1 hour (abandonedCheckoutCron.js)
  ↓
Identifies orders not completed within 24 hours
  ↓
Records saved to abandonedcheckouts collection
  ↓
Email sent to customer with recovery link
  ↓
Customer clicks link and returns to checkout
  ↓ (POST /api/orders/complete)
Completes payment
  ↓
Order moves to confirmed state


4. BOOKING/APPOINTMENT WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Customer visits /book-appointment (my-app)
  ↓
Selects date, time, service type
  ↓ (POST /api/booking)
Backend saves to bookings collection
  ↓
Confirmation email sent to customer
  ↓
Notification email sent to admin
  ↓
Booking appears in Admin Dashboard
  ↓
Admin can:
  - Confirm booking
  - Reschedule booking
  - Cancel booking
  ↓
Customer receives email notification of status change


5. ORDER TRACKING WORKFLOW
━━━━━━━━━━━━━━━━━━━━━━━━

Order shipped with Shipment document created
  ↓
Shipment has tracking_id from logistics provider
  ↓
Tracking Cron (trackingCron.js) runs every hour
  ↓
Queries shipping providers (Blue Dart, Delhivery, DHL)
  ↓
Receives tracking updates
  ↓
Creates TrackingEvent documents in DB
  ↓
Customer can view tracking (GET /api/track/:tracking_id)
  ↓
Real-time location & status updates displayed

================================================================================
CRON JOBS
================================================================================

1. ABANDONED CHECKOUT CRON (abandonedCheckoutCron.js)
   ├─ Runs: Every 1 hour
   ├─ Logic:
   │  ├─ Query orders with status = "pending"
   │  ├─ CreatedAt > 24 hours ago
   │  └─ Payment status = failed/timeout
   ├─ Action:
   │  ├─ Save to abandonedcheckouts collection
   │  ├─ Send recovery email with checkout link
   │  └─ Log abandoned checkout
   └─ Triggers: Email notifications

2. TRACKING UPDATE CRON (trackingCron.js)
   ├─ Runs: Every 1 hour
   ├─ Logic:
   │  ├─ Query all active shipments
   │  ├─ For each shipment, query provider API
   │  └─ Check for new tracking updates
   ├─ Action:
   │  ├─ Create new TrackingEvent document
   │  ├─ Update shipment status if changed
   │  └─ Log tracking update
   └─ Triggers: Real-time tracking updates


================================================================================
AUTHENTICATION & AUTHORIZATION
================================================================================

BACKEND MIDDLEWARE (middleware/auth.js):
├─ Route: All /api/* endpoints
├─ Middleware: verifyToken()
├─ Logic:
│  ├─ Extract JWT from Authorization header
│  ├─ Verify JWT signature with JWT_SECRET
│  ├─ Decode token to get admin ID & role
│  └─ Attach decoded data to req.user
├─ If invalid:
│  └─ Return 401 Unauthorized
└─ If valid:
   └─ Continue to route handler

ADMIN PANEL AUTHENTICATION:
├─ Route: /login (admin/src/LoginPage.tsx)
├─ On mount:
│  └─ Check localStorage for admin_token
├─ If exists:
│  └─ Show Dashboard (authenticated state)
├─ If not:
│  └─ Show LoginPage
├─ On login form submit:
│  ├─ POST to /api/auth/login
│  ├─ Receive token + username
│  ├─ Store in localStorage
│  └─ Update local state → show Dashboard
└─ On logout:
   ├─ Remove token from localStorage
   └─ Clear local state → show LoginPage

CUSTOMER FRONTEND:
├─ No admin authentication needed
├─ Guest browsing allowed
├─ Order creation can be guest or logged-in
└─ Tracking via public endpoint (GET /api/track/:id)

================================================================================
TROUBLESHOOTING GUIDE
================================================================================

Issue: API calls fail with CORS error
├─ Check: ALLOWED_ORIGINS in .env
├─ Solution: Add frontend URL to ALLOWED_ORIGINS
└─ Example: ALLOWED_ORIGINS=http://localhost:5173,http://localhost:5174

Issue: Database connection fails
├─ Check: MONGODB_URI in .env
├─ Solution: Verify MongoDB Atlas cluster IP whitelist
└─ Test: Use MongoDB Compass to connect

Issue: Email not sending
├─ Check: EMAIL_USER and EMAIL_PASS in .env
├─ Solution: Generate Gmail App Password (not regular password)
├─ Enable: Less secure app access
└─ Test: Send test email via POST /api/notifications/send

Issue: Shipping provider API error
├─ Check: API keys in .env
├─ Solution: Verify credentials with logistics provider
└─ Test: Use provider's test API endpoint

Issue: Payment not being verified
├─ Check: RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET
├─ Solution: Use correct key for environment (test/live)
└─ Test: Use Razorpay test card numbers

Issue: Images not uploading
├─ Check: Cloudinary credentials
├─ Solution: Verify API key and secret
└─ Test: Use Cloudinary API directly
