6. PAYMENT FLOW VERIFICATION
----------------------------

This application implements a Razorpay-based workflow with layered validation. Based on code inspection and tests, the following payment lifecycle is present:

1. User selects a cart or product.
2. Frontend initiates /api/payments/create-order.
3. Backend recalcualtes cart totals from database and validates the cart.
4. Backend creates PaymentAttempt and creates Razorpay order.
5. Razorpay checkout opens with key and order metadata.
6. User completes payment externally.
7. Frontend sends verification data to /api/payments/verify.
8. Backend validates HMAC signature and compares order, amount, and payment data.
9. If valid, backend marks captured payment and updates Order status.
10. Backend calls order fulfillment updates and email sending path.
11. Frontend polls status and redirects appropriately.

Status for real payment lifecycle:
- Successful live payment: NOT TESTED
- Failed/cancelled payment: NOT TESTED live
- Timeout / network interruption: NOT TESTED live
- Invalid signature rejection: PASSED in automated backend tests
- Duplicate verification: PASSED in automated backend tests
- Duplicate webhook processing: PASSED in automated backend tests
- Concurrent payment attempts: PASSED in automated backend tests
- Webhook authenticity: PASSED in automated backend tests
- Live Razorpay account checkout: BLOCKED / NOT TESTED

Important security requirement check:
- The backend does not trust frontend success alone. Verified by server-side validation logic.
- Payment secrets are stored server-side in backend/.env, which is not safe for client exposure.
- Live payment verification with actual Razorpay was not executed in this session; no live transaction result may be claimed.
